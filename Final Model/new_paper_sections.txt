IV. DATASET GENERATION AND PREPROCESSING
====================================================================

A. Dataset Sources and Composition

Our model leverages comprehensive QKD simulation data aggregated 
from multiple protocol-specific datasets. The training corpus 
comprises six distinct data sources:

    1. BB84 dataset (qkd_final_*.csv)
    2. BBM92 dataset (bbm92_*.csv)
    3. Decoy-BB84 dataset (decoybb84_*.csv)
    4. SARG04 dataset (sarg04_*.csv)
    5. Six-State dataset (sixstate_*.csv)
    6. Novel Protocols dataset (novel_protocols_*.csv)

The final consolidated dataset contains 36,000 validated samples
after preprocessing and quality filtering, representing simulations
across diverse quantum channel conditions.

B. Supported Protocols

The system supports nine QKD protocols spanning traditional and 
novel operational regimes:

    - AB-QKD (Adaptive Basis QKD)
    - B92 (Two-state Bennett 1992)
    - BB84 (Bennett-Brassard 1984)
    - BBM92 (Simplified Entanglement-based)
    - DS6-QKD (Decoy Six-State)
    - Decoy-BB84 (Decoy State BB84)
    - EEPM-QKD (Entanglement-Enhanced Prepare-Measure)
    - SARG04 (PNS-resistant protocol)
    - Six-State (Three-basis protocol)

C. Quantum Hardware Platforms

Training data incorporates simulations across four distinct 
quantum computing architectures:

TABLE I: Supported Quantum Platforms
+----------------------+-------------------+
| Platform             | Type              |
+----------------------+-------------------+
| IonQ Aria           | Trapped Ion       |
| IonQ Harmony        | Trapped Ion       |
| Rigetti Aspen-M-3   | Superconducting   |
| OQC Lucy            | Superconducting   |
+----------------------+-------------------+

Platform-specific characteristics including qubit fidelities and
coherence times are implicitly captured through the training data
distributions.

D. Parameter Ranges

Dataset generation encompassed the following parameter space:

    - Distance: 5 - 250 km (transmission distance)
    - Noise Factor: 1.0 - 2.5 (environmental noise multiplier)
    - Secure Key Rate: 0.0 - 0.571 (normalized)
    - Transmission: 1e-5 - 0.794 (channel transmission efficiency)

E. Data Preprocessing Pipeline

The preprocessing pipeline implements several transformation stages:

    1. Column Standardization: Harmonizes column names across 
       heterogeneous dataset formats (e.g., 'qber' -> 'qber_total')

    2. Feature Extraction: Selects relevant features:
       - Inputs: protocol, platform, distance_km, noise_factor
       - Outputs: secure_key_rate, transmission

    3. Data Cleaning:
       - Removal of rows with missing values
       - Exclusion of negative secure key rates
       - Outlier removal (values beyond 3 standard deviations)

    4. Categorical Encoding:
       - Protocol names: LabelEncoder transformation
       - Platform names: LabelEncoder transformation

    5. Feature Scaling:
       - StandardScaler applied to numerical features
       - Mean normalization with unit variance

F. Train/Test Split

The dataset undergoes stratified splitting:

    - Training Set: 80% (28,800 samples)
    - Test Set: 20% (7,200 samples)
    
Additional validation split from training data:
    - Training: 64% of total (23,040 samples)
    - Validation: 16% of total (5,760 samples)
    - Test: 20% of total (7,200 samples)

V. NEURAL NETWORK ARCHITECTURE
====================================================================

A. Model Design Philosophy

Our approach employs a deep neural network architecture with 
multi-output regression capability, predicting both secure key 
rate and transmission coefficient simultaneously. This dual-output
design enables holistic QKD performance assessment from a single
inference pass.

B. Network Architecture

The model follows a feed-forward architecture with progressive
dimensionality reduction:

    Input Layer: 4 features
        [protocol_encoded, platform_encoded, distance_km_scaled, 
         noise_factor_scaled]
    
    Dense Block 1:
        - Dense Layer: 128 neurons, ReLU activation
        - Batch Normalization
        - Dropout: 20%
        - L2 Regularization: lambda = 0.001
    
    Dense Block 2:
        - Dense Layer: 64 neurons, ReLU activation
        - Batch Normalization
        - Dropout: 20%
        - L2 Regularization: lambda = 0.001
    
    Dense Block 3:
        - Dense Layer: 32 neurons, ReLU activation
        - Batch Normalization
        - Dropout: 10%
        - L2 Regularization: lambda = 0.001
    
    Dense Block 4:
        - Dense Layer: 16 neurons, ReLU activation
    
    Output Layer: 2 neurons, Linear activation
        [secure_key_rate, transmission]

C. Regularization Strategies

Multiple regularization techniques prevent overfitting:

    1. L2 Weight Regularization (lambda = 0.001):
       Penalizes large weight magnitudes in dense layers

    2. Dropout Regularization:
       - 20% dropout in early layers
       - 10% dropout in deeper layers

    3. Batch Normalization:
       Normalizes layer activations for training stability

D. Optimization Configuration

    Optimizer: Adam (Adaptive Moment Estimation)
    Learning Rate: 0.001 (initial)
    Loss Function: Mean Squared Error (MSE)
    Metrics: MAE, MSE

E. Training Callbacks

Intelligent training control mechanisms:

    1. Early Stopping:
       - Monitor: validation loss
       - Patience: 20 epochs
       - Restore best weights: enabled

    2. Learning Rate Reduction:
       - Monitor: validation loss
       - Factor: 0.5 (halve LR on plateau)
       - Patience: 10 epochs
       - Minimum LR: 1e-6

    3. Model Checkpointing:
       - Save best model based on validation loss
       - Format: Keras native (.keras)

F. Fallback Architecture (sklearn Ensemble)

For environments without TensorFlow, an ensemble fallback 
provides robust predictions:

    Component Models:
        - Gradient Boosting Regressor (weight: 0.4)
            * 200 estimators, max_depth=6, learning_rate=0.1
        - Random Forest Regressor (weight: 0.3)
            * 200 estimators, max_depth=10
        - MLP Regressor (weight: 0.3)
            * Architecture: 128-64-32-16 neurons
            * Early stopping enabled

    Weighted ensemble prediction combines component outputs
    for final multi-output regression.

VIII. CONCLUSIONS AND FUTURE SCOPE
====================================================================

A. Key Contributions

This work establishes a neural network-based approach for QKD
performance prediction and protocol recommendation:

    1. Multi-Output Prediction Model:
       Deep neural network simultaneously predicting secure key
       rate and transmission efficiency achieves 96.42% overall
       R-squared accuracy.

    2. Ten-Protocol Support:
       Comprehensive coverage of QKD protocols including BB84, BBM92,
       SARG04, Six-State, Decoy-BB84, E91, B92, AB-QKD, DS6-QKD,
       and EEPM-QKD.

    3. Platform-Aware Predictions:
       Model implicitly captures platform-specific characteristics
       for IonQ (trapped-ion) and Rigetti/OQC (superconducting)
       architectures.

    4. User-Centric Design:
       Three-input interface (distance, platform, noise) minimizes
       user complexity while maintaining predictive accuracy.

    5. Production-Ready Implementation:
       Complete preprocessing pipeline, training scripts, and
       interactive prediction interface enable immediate deployment.

B. Technical Achievements

    - Secure Key Rate R-squared: 0.9317
    - Transmission R-squared: 0.9968
    - Overall R-squared: 0.9642
    - Dataset Size: 36,000 validated samples
    - Protocol Coverage: 10 QKD protocols
    - Platform Coverage: 4 quantum architectures

D. Limitations

Current implementation limitations include:

    1. Simulation-Based Training:
       Model trained on simulated data; real quantum hardware
       validation remains pending.

    2. Static Channel Assumptions:
       Model does not address time-varying channel conditions
       or adaptive real-time updates.

    3. Platform Generalization:
       Training limited to four quantum architectures;
       generalization to emerging platforms requires retraining.

    4. MAPE Sensitivity:
       Mean Absolute Percentage Error elevated for transmission
       due to near-zero values in some predictions.

E. Future Work

    1. Hardware Validation:
       Deploy model on commercial quantum platforms via
       Amazon Braket or IBM Quantum to validate simulation accuracy.

    2. Online Learning:
       Implement continual learning mechanisms for model updates
       from real-world deployments.

    3. Time-Series Extension:
       Incorporate temporal dynamics for channels with time-varying
       characteristics.

    4. Quantum Repeater Integration:
       Extend model to predict optimal repeater placement for
       ultra-long-distance QKD networks.

    5. Uncertainty Quantification:
       Add prediction confidence intervals through Bayesian
       neural network or ensemble variance estimation.

    6. Novel Protocol Development:
       Use model insights to guide development of protocols
       optimized for specific channel conditions.

F. Concluding Remarks

This neural network-based QKD prediction system demonstrates that
deep learning can effectively model the complex relationships
between quantum channel parameters and secure key distribution
performance. By achieving 96.42% prediction accuracy across
multiple outputs and supporting nine distinct protocols, this
work establishes a foundation for intelligent, adaptive quantum
cryptographic systems.

The multi-output architecture represents an advancement over
single-target approaches, enabling simultaneous optimization of
secure key rate and transmission efficiency. As quantum networks
evolve toward metropolitan and intercity deployments, such
predictive capabilities will prove essential for extracting
maximum performance from heterogeneous quantum infrastructure.
